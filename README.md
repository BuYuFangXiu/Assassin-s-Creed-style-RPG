## ✅ 已完成功能

### 1. 移动与跑酷系统

**核心功能：**
- **角色移动组件配置**：最大行走速度 300cm/s、跑步速度 600cm/s、加速度 1500、转向速率 360。

  <img src="视角转动与移动.gif" alt="视角转动演示" width="300">

- **蹲伏系统**：按下 C 切换，角色进入 crouch 状态，胶囊体半高从 90 缩至 70，相对位置的 Z 轴从-89增加为-69，移动速度降至最大 250，摄像头距离从 300 过渡到 400。
- **跑酷翻越**：按下空格键触发动态多点检测（球体追踪 + 线段追踪），通过循环计算障碍物的起始点、中间点、落点，成功后使用 `Motion Warping` 播放翻越动画。
- **动态倾斜**：根据角色角速度，在动画蓝图中对 Spine 骨骼进行 X 轴旋转偏移，最大倾斜角度 25°。
- **动画驱动**：使用 `Blend Space` 1D 根据速度大小切换 idle/walk/jog/sprint 动画；使用 `Blend Space` 2D 根据速度方向和移动方向切换 strafe 动画。



**技术要点：**
- 核心变量包括：
  - Speed（浮点型）：用于驱动行走 / 跑步动画的速度参数，实现不同移动速率下的动画过渡；
  - Direction（浮点型，范围 - 180~180）：控制角色移动方向（前后 / 左右）的动画混合，实现平滑的转向动作；
  - IsCrouching（布尔型）：标记角色蹲伏状态，用于切换站立 / 蹲伏动画及调整角色姿态；
  - IsSprinting（布尔型）：标记冲刺状态，用于切换跑步 / 冲刺动画，适配不同移动节奏。
- 翻越检测：
  - 从角色眼部位置（高位射线）与膝盖位置（低位射线）各发射一条检测射线，同步校验路径是否无阻挡、障碍物高度是否处于可翻越范围；
  - 高位射线确保翻越过程中角色不会被上方物体阻挡，低位射线校验障碍物底部空间是否满足通行条件，两者结合判定翻越可行性。
- 蹲伏状态碰撞适配：
  - 将 Pawn 碰撞预设切换为适配蹲伏姿态的胶囊体半高尺寸，缩小碰撞体垂直高度；
  - 避免角色在头部上方空间（如头顶岩石）中因碰撞体因没判断上方是否有预留空间从而导致的玩家穿模、卡死等问题，确保蹲伏移动的流畅性与碰撞合理性。

### 2. 战斗系统

**核心功能：**
- **连续攻击**：鼠标左键攻击（四段连击）。
- **连击窗口**：每次攻击动画播放到 60%左右（不同动画有所差异） 位置时开启连击检测窗口，连续点击攻击，会存放下一次攻击，这次攻击动画播放完成时会再次播放下一击。
- **命中检测**：武器会附加一个线性球体碰撞，在攻击动画的特定帧启用碰撞，重叠到敌人后调用 `Apply Damage`。
- **伤害计算**：基础攻击力 × 攻击类型系数 ，后续可根据等级装备改变。
- **敌人反应**：收到伤害后播放受伤动画，血量归零时播放死亡动画并禁用 AI。

**技术要点：**
- 使用不同伤害追踪手段设置攻击。
- 连击计数器（`ComboCount` 0~2）用于决定播放哪一段攻击动画。

### 3. 潜行与暗杀

**核心功能：**
- **潜行模式**：按 C 切换，角色进入 crouch 状态，也就是蹲伏状态。
- **背刺判定**：潜行状态下靠近敌人背后根据 `Assassin REF` 的位置，与之重叠后，敌人头顶会出现 `[RM]ASSASSINATE` 提示，点按 `鼠标右键` 会进行动作扭曲触发处决动画。
- **处决逻辑**：播放蒙太奇期间将敌人设置为无敌并隐藏 AI 控制器，动画结束时应用巨量伤害（秒杀）。

**技术要点：**
- 敌人感知组件使用 `AISense_Sight` 配置：丧失视力距离 1500cm，视野半角 60°，每 0.5 秒更新。
- 背刺判定使用球体碰撞，设置 `Assassin REF` 的位置。

### 4. 敌人 AI

**核心功能：**
- **行为树结构**：Root → Selector（优先级从上到下）
  - 战斗状态：Chase Target Sequence（追击 → 攻击）
  - 警戒状态：Investigation Sequence（调查噪音 → 搜索目标）
  - 巡逻状态：Patrol Sequence（走到下一点 → 等待 2 秒 → 循环）
- **黑板 Key**：`SelfActor`（Object）、`TargetActor`（Object）、`InMeleeAttackRange`（Bool）、`Investigation Location`（Vector）。
- **感知系统**：
  - 视觉：视野 100°，半径 1000，自动失去目标距离 1500。
  - 听觉：半径 1500，暂不支持玩家的脚步声，目前可以通过投掷物品发出的声音使AI"听到"。
- **攻击逻辑**：距离 >120 时接近，距离 <140 时进入攻击距离，<120 时停止移动并攻击。

**技术要点：**
- 使用 `TargetActor`键来判断是否有目标来决定执行追逐战斗还是执行随机巡逻，如果`TargetActor`键不为空则会追逐目标，进入攻击范围并且到达目标跟前则会攻击！
- 巡逻点通过 `Investigation Location` 来判断是否有需要调查的目标，如果有则会前去调查并停留，没有则会随机巡逻。

### 5. 属性与装备系统

**核心功能：**
- **玩家属性**（存储在 `BP_Player` 中）：
  - 生命值（100 → 随着升级会不断升高）
  - 体力值（100，用于跑步/重击消耗，每秒恢复 7，后面体力增加方案敬请期待）
  - 攻击力（武器伤害值，简单设置，后续可能会乘一个初始值攻击力）
  - 等级（1-50(?并未设限)，每级经验需求 = 100 × 等级）
  - 经验值（杀敌 +50，完成任务 +200）
- **装备数据表**（DataTable）：
  - 列：Name（字符串）、Damage（浮点）、Required Level（整数）、Icon（纹理 2D）、Static Mesh（静态网格体）、type（E Weapon Type 枚举）、Weapon Socket（字符串）。
- **装备系统**：拾取武器后，调用 `AttachActorToComponent` 将武器模型附加到角色的手部插槽，属性加成实时更新。
- **升级算法**：经验值达到升级阈值后等级+1，生命值 / 攻击力按公式提升，体力值补满。

**技术要点：**
- 装备数据表使用 `DB_Weapon` 存储
- 装备核心数据模型与 UI 交互层的联动设计与可视化实现

### 6. UI 与交互

**核心功能：**
- **主 HUD**：包含血条（Progress Bar）、体力条、经验条、当前武器和装备图标。
- **动态绑定**：血条百分比 = 当前生命值 / 最大生命值，体力条相同，经验条 = 当前经验 / 下一级需求经验。
- **视角锁定系统**：按中键时，会射出长度 1000cm、半径为 100 的球体追踪扫描正前方范围最先与球体追踪发生碰撞的贴有 `Damageable` 标签的东西，切换 `TargetLock` 状态，相机持续注视目标（`Find Look at Rotation`）。
- **交互提示**：按 E 会在视野中心发射球体追踪检测，命中 “BP_Weapon” 蓝图的物体后会将“BP_Weapon” 蓝图计入S_Slots结构体的数据表里并销毁这个蓝图，给人一种好像真的捡入背包的感觉。

**技术要点：**
- 锁定系统使用 事件tick实时改变视角角度，使视角实时追踪锁定的目标身上。
- 交互检测使用 球体追踪，忽略玩家自身和其他不相关的物体。

### 7. 攀爬系统

**核心功能：**
- **垂直攀爬**：角色贴近墙壁时，按 ALT 键（可根据自身习惯更改）进入攀爬状态，支持上下左右移动，使用 `Blend Space` 2D  适配不同方向和速度的攀爬动画。
- **边缘检测**：通过射线检测墙壁顶部边缘，到达边缘后自动播放翻身上台动画。
- **攀爬耐力**：攀爬过程中持续消耗体力，体力耗尽自动跌落。（暂时关闭，感觉可能体验不是很好）
- **横向平移**：在攀爬状态下可沿墙壁横向移动，支持跨越窗台、绕过凸起，根据墙面不同角度改变自身角度使之贴合。
- **跳攀**：如果边缘检测判定为true则会不进入攀爬模式直接播放翻身上台动画。

**技术要点：**
- 使用线条追踪寻找可攀爬表面。
- 边缘检测：从角色头部上方向前发射多条射线，检测顶部边缘位置。

### 8. 任务系统

**核心功能：**
- **任务类型**：主线任务、支线任务、赏金任务。
- **任务目标**：到达指定地点、击杀指定敌人、收集物品、护送 NPC。
- **任务追踪**：HUD 显示当前任务目标及距离，按 Tab 打开任务日志。
- **任务奖励**：完成任务后获得经验值、金币、装备。
- **任务触发**：与 NPC 对话、进入特定区域、击杀特定敌人后自动触发。
- **任务进度保存**：支持任务状态（未接取/进行中/已完成/失败）的持久化存储。

**技术要点：**
- 使用 `DataTable` 存储任务配置（任务 ID、名称、描述、目标类型、奖励）。
- 任务目标使用 `GameplayTag` 标记，方便查询和进度更新。
- 任务日志 UI 使用 `ListView` 动态生成条目。
- 进度保存：通过 `SaveGame` 对象存储任务完成状态，游戏加载时恢复。

#### 🔍 遇到的 Bug & 解决方案

<h4 id="bug-vault-loop">🐞 翻越动画重复播放</h4>

- **现象**：在角色判定正面的网格体可以翻越后，翻越动画已经开始播放，如果快速点击翻越功能按钮，角色会多次重复播放翻越动画。
- **原因**：多次翻越动画相互覆盖，缺少判定状态变量。
- **解决方案**：加入名为 `IsVaulting` 的变量，在播放翻越动画之前设置 `IsVaulting = true`，在翻越动画播放完成时设置 `IsVaulting = false`（默认为 false）。

<h4 id="bug-camera-shake">🐞 翻越时镜头闪烁 / 被拉近</h4>

- **现象**：角色翻越过程中，镜头出现明显闪动，被墙体阻挡后瞬间拉近，角色稍微移动后又拉回原位，反复切换造成闪烁。
- **原因**：UE 相机碰撞系统（`CameraBoom`）在角色贴墙时被墙体碰撞体阻挡，引擎自动拉近镜头避免穿模；角色动作移动后障碍不再遮挡，镜头又拉回，反复切换导致闪烁。
- **解决方案**：翻越动画开始前临时禁用相机碰撞（调用 `Set Do Collision Test` 设为 `false`），动画结束后恢复。

<h4 id="bug-vault-close-distance">🐞 近距离贴墙不触发翻越</h4>

- **现象**：角色离墙较近（如 20cm 以内）时，按翻越键没有任何反应，无法触发翻越逻辑。
- **原因**：射线检测起点被墙体碰撞体包住，UE 默认不检测起点所在碰撞体内部，导致射线穿模、检测失效；距离判断最小值设置过大（如 50cm），贴墙时距离不满足条件被逻辑过滤。
- **解决方案**：给射线起点加向后偏移（15-30cm），确保起点永远在墙体外面；找到距离判断节点（`Is In Range`），把最小值从 50cm 改成 10cm。

<h4 id="bug-set-collision">🐞 错误调用「设置 Actor 启用碰撞」节点导致游戏卡顿与角色穿模</h4>

- **现象**：在翻越逻辑中调用该节点后，游戏会出现明显的瞬间卡顿、画面冻结，同时角色会出现翻越时穿过墙体、动画位置错乱等穿模问题。
- **原因**：该节点会一次性关闭/开启整个角色 Actor 的所有组件碰撞，一方面会触发 UE 物理引擎的全量碰撞更新与碰撞体重注册，产生高额性能开销造成卡顿；另一方面会将角色从物理碰撞检测列表中完全移除，失去与地面、墙体的碰撞约束，同时破坏角色自身的碰撞逻辑，最终引发各类穿模问题。
- **解决方案**：优先直接删除该节点，靠「设置运动模式为 None」即可避免角色被墙体碰撞推挤打断动画，无需额外关闭碰撞；若仍需规避碰撞干扰，仅**单独关闭角色胶囊体组件的碰撞**，不要关闭整个 Actor 的碰撞，既不会产生性能卡顿，也能避免角色掉出地图的穿模风险。

<h4 id="bug-crouch-jump">🐞 蹲下时仍然可以跳跃</h4>

- **现象**：在蹲下后跳跃指令还是正常工作，主流游戏中应为蹲下后，输入跳跃指令，人物会先返回站立姿态，再次输入跳跃指令才会执行跳跃。
- **原因**：没有判断在蹲下或者站立的状态，是否执行跳跃或其他。
- **解决方案**：自定义事件中先判断是否下蹲，若为 `true`，则切换到站立状态；若为 `false`，则执行跳跃。

<h4 id="bug-crouch-animation">🐞 蹲下逻辑正常但动画不播放</h4>

- **现象**：蹲下流程完全执行，镜头正常缩放，但动画始终不切换到蹲下状态。
- **原因**：动画蓝图的 `IsCrouch` 变量未与玩家蓝图的 `Crouch?` 变量同步，动画状态机无法识别蹲下信号。
- **解决方案**：在动画蓝图的「事件蓝图更新动画」中，实时获取玩家角色的 `Crouch?` 并赋值给 `IsCrouch`。

### 战斗系统开发笔记

> 🚧 **待补充**：连击窗口、蓄力重击、命中检测的调试过程等。

#### 🔍 遇到的 Bug & 解决方案

<h4 id="bug-assassination-offset">🐞 刺杀时玩家与敌人错位</h4>

- **现象**：即使使用了运动扭曲，触发刺杀后玩家还是未站在敌人背后正确位置，出现左右/前后巨大偏移。
- **原因**：播放【蒙太奇动画】的引线和后面【添加或更新扭曲目标】的节点的引线连接错误，将【蒙太奇动画】的「完成时」引线连入了【添加或更新扭曲目标】的执行引脚。
- **解决方案**：将【蒙太奇动画】的**执行引脚**连入【添加或更新扭曲目标】的执行引脚（而非「完成时」）。

<h4 id="bug-sphere-trace">🐞 球形追踪失效（武器无碰撞体）</h4>

- **现象**：武器球形追踪功能异常，排查过程中发现蓝图设计没有问题，但更换武器模型后跟踪功能恢复正常，原模型存在角色可直接穿模、无物理阻挡的情况，最终定位到跟踪失效的根源为模型碰撞问题。更改碰撞设置同样无效，最终得出球形追踪功能异常由**武器静态网格体没有碰撞体积**造成。
- **原因**：核心根源为模型无有效碰撞体。球形跟踪依赖静态网格体的碰撞体进行射线/重叠检测，原剑模型为外部导入资源，未生成可用的简单碰撞体，导致跟踪检测无法命中，功能失效；更换的模型自带有效碰撞体，跟踪功能恢复正常。碰撞设置错误：未配置物理引擎可识别的简单碰撞（胶囊/盒子/球体），导致跟踪检测无有效碰撞体可命中。
- **解决方案**：为模型生成有效碰撞体：在静态网格体编辑器中，通过「碰撞」菜单手动创建胶囊体/盒子碰撞，调整线框完整包裹模型，通过视图「显示 - 碰撞」功能验证白色碰撞线框正常显示。导入阶段前置配置：后续导入外部模型时，在导入设置中勾选「自动生成简单碰撞」，从源头避免碰撞缺失导致的跟踪失效问题。可视化验证：通过碰撞可视化功能，快速校验模型碰撞体是否生效，提前排查跟踪功能的潜在故障。

### 敌人 AI 开发笔记

> 🚧 **待补充**：行为树优先级调整、感知参数优化、巡逻点动态生成等。

#### 🔍 遇到的 Bug & 解决方案

<h4 id="bug-ai-target-self">🐞 AI 追逐目标始终为自身</h4>

- **现象**：AI 感知系统能正常触发，行为树也能进入追逐分支，但 AI 始终原地不动；打印调试发现，黑板中存储的目标 Actor 为 AI 控制器自身（`BP_AI`），而非玩家角色，导致追逐逻辑始终以 AI 自身为目标。
- **原因**：核心根源为任务蓝图中黑板键变量未正确绑定，导致任务始终读取默认值而非黑板数据：任务蓝图中的 `Target Actor` 变量虽为黑板键选择器类型，但在行为树节点中未绑定黑板键，导致任务运行时读取的是变量默认值（AI 自身），而非黑板中更新的玩家对象。误将黑板键选择器当作普通 Actor 变量处理，错误设置了默认值为 AI 自身，进一步导致任务始终使用默认值，忽略黑板中的玩家目标。
- **解决方案**：正确绑定黑板键：在行为树编辑器中，选中追逐任务节点，在细节面板中为 `Target Actor` 变量绑定黑板中的 `Target Actor` 键，确保任务能读取黑板数据。清除无效默认值：将任务蓝图中 `Target Actor` 变量的默认值设置为 `None`，避免默认值干扰黑板数据读取。验证逻辑闭环：运行游戏，通过行为树编辑器实时监控黑板键值，确认 AI 感知到玩家后，黑板中 `Target Actor` 键值更新为玩家角色，同时打印调试任务中获取的目标对象，验证为玩家而非 AI 自身。

### 属性与装备系统开发笔记

> 🚧 **待补充**：属性广播事件、装备数据表动态加载等。

#### 🔍 遇到的 Bug & 解决方案

<h4 id="bug-stamina-not-cost">🐞 冲刺体力不消耗</h4>

- **现象**：按住冲刺键后，即使角色正常奔跑达到最大速度，体力也始终不消耗；或按下冲刺键后完全没有体力消耗的反应。
- **原因**：速度判断逻辑仅在按下冲刺键的瞬间执行 1 次，角色加速需要时间，刚按下时实际速度未达到阈值（700），判定为 False 导致定时器未启动；且速度值仅在按键瞬间更新，后续角色速度上升后不会重新触发判断，永远无法满足消耗条件。
- **解决方案**：将“获取速度 → 向量长度 → ≥700”的判断逻辑移至 `Drain Stamina` 自定义事件中；按下冲刺键时直接启动定时器，无需先判断速度；定时器每 0.1 秒执行一次 `Drain Stamina`，每次执行前先判定当前速度是否 ≥700，满足则执行 `Decrease Stamina` 消耗体力，不满足则跳过消耗逻辑。

### 通用问题与故障排除

#### 🔍 遇到的 Bug & 解决方案

<h4 id="bug-component-lost">🐞 人物组件与变量引用丢失，需重新指定</h4>

- **现象**：蓝图提示变量无效、组件获取失败，部分功能无法正常运行。
- **原因**：删除相关资产后，原有的组件引用、变量绑定一并丢失，未重新关联。
- **解决方案**：在玩家蓝图中重新拾取对应组件，替换并重新绑定所有失效的变量与对象引用。

<h4 id="bug-common-component-null">🐞 敌我通用组件身份判断失效，变量空指针报错</h4>

- **现象**：PIE 运行时持续报“结果为无”“无访问”，敌人生成后报错加剧，玩家 XP/等级 UI 正常，敌人逻辑异常。
- **原因**：`Event Tick` 内的 XP、等级、玩家专属 UI 更新逻辑，未加 `IsPlayer` 前置判定，敌我组件每帧都会执行这段逻辑；敌人组件内 `Player Character BP` 为空，强行访问直接触发空指针报错。
- **解决方案**：在所有玩家专属逻辑的执行入口，加 `Branch` 分支节点，条件为 `IsPlayer == true`，仅 `true` 分支执行玩家 XP/等级/专属 UI 更新逻辑，`false` 分支直接断开不执行，彻底隔离敌我执行路径。
